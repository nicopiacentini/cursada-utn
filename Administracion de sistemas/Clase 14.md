#### Ciclo de calidad
1. Identificacion de politica de calidad
2. Planificacion de acciones de calidad -> HACER PLAN DE TESTING PARA DEFINIR CON EL CLIENTE. LUEGO SE PASA A PRODUCCION
3. Aseguramiento de calidad -> Hago tareas para que mi producto llegue a una calidad. Que hago de antemano para llegar a un nivel de calidad esperado. (prevencion)
4. Control y seguimiento de calidad -> Pruebo mi producto para que sea de calidad (inspeccion)
5. Cierre
La calidad no se inyecta sino que se gestiona

### Grado de calidad
Es cuanto las caracteristicas de un producto, servicio o proceso cumple con requisitos
#### Para un proyecto...
Es la capacidad del proyecto para satisfacer requisitos y expectativas de cliente asi como capacidad de proyecto para cumplir con los estándares de calidad definidos

#### Satisfaccion de cliente
Como se si cumplo con la satisfaccion de un cliente? TENER UNA FASE DEDICADA A TESTING NO FUNCIONAL

### Costos de calidad y no calidad
#### De no calidad
Costos que se asumen por no llegar al nivel de calidad pedido. Basicamente el retrabajo. Lo asume el beneficio
##### Costos de fallas internas
Son originados por defectos detectados antes que el producto llegue al cliente
##### Costos de evaluación
Son ocacionados por defectos detectados despues de la entrega al cliente
#### De calidad
Costos que se asumen para llegar a un nivel de calidad. Lo asume el cliente
##### Costos de prevencion
Se destinan a evitar que se produzcan defectos.
##### Costos de evaluación
Verifica que el producto cumple con requisitos de calidad previo a entrega

### Rol del PM con respecto a calidad
La calidad me determina el alcance de proyecto. El PM debe:
1. Recomendar mejoras en procesos y políticas de calidad
2. Establecer métricas para medir la calidad
3. Revisar la calidad antes de finalizar el entregable
4. Evaluar el impacto en la calidad cada vez que cambia el alcance, tiempo, costo, riesgos y recursos
5. Destinar tiempo para realizar mejoras de calidad
6. Asegurar que se utilice el control integrado de cambios. Basicamente para hacer un seguimiento de los cambios en el proyecto (cambios en alcance, tiempo, costos, calidad, etc.)
		Se tiene que definir una politica para definir estos cambios

#### Dentro de Acta de proyecto
1. Debo poner supuestos. Son asumciones que debo hacer para mi proyecto. La responsabilidad de dicho supuesto NO es del proyecto sino que es para la empresa u otro. Decir "Se asume..."
2. Identifico restricciones. Son acciones que se consideran bloqueantes en el proyecto. Se consideran responsabilidad del usuario, cliente/sponsor del proyecto.
